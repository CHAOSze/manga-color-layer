# Manga coloring and animation layers

Preserve the approved expression, gesture, silhouette, material colors and manga texture. Carry user corrections and accepted feature treatments forward through rebuilds. Keep previously requested independent controls unless the user revises them. Prefer a continuous merged part where separation is unreliable and independent movement is unnecessary; do not maximize layer count. Fidelity means perceptual agreement unless exact pixels are explicitly required.

A movable material plate should normally contain coherent, connected artwork, including its hidden joins. Placing disconnected extraction scraps in one layer does not make them a continuous Puppet surface. Keep opaque illustrated materials at full interior alpha as well as 100% layer opacity; distinguish intentional exterior/strand gaps and narrow antialiasing from unwanted translucent paint. Weigh local boundary redraw or simpler grouping above exact pixel reconstruction when these conflict.

## Adapt to each request
Do not carry a previous character’s palette, anatomy, layer count, grouping, motion range, canvas size or backend into a new task. Establish the subject, source/reference roles, style, required motions and deliverable first. A coloring-only request needs no layer workflow; a layer-only request needs no recoloring. Select part granularity and completion depth from the current pose and animation, including facial animation, articulated limbs, accessories or nonhuman features when present. Examples in the references illustrate decisions, not default partitions.

## Workflow
1. Locate and inspect the original drawing, color reference, latest approved output and any supplied PSD. Use original attachments to resolve disputed anatomy/materials; prior generated images and confident descriptions are not evidence.
2. For coloring, read [coloring.md](references/coloring.md). Establish structure versus palette reference roles and inspect ambiguous prop/skin boundaries before recoloring.
3. For animation, establish intended motion from existing context and read [motion-first.md](references/motion-first.md). Analyze a supplied PSD using [reference-driven-parts.md](references/reference-driven-parts.md), adapting construction principles rather than its layer count.
   For independent eyes, mouth, gaze, blinking or mouth-shape controls, read [facial-parts.md](references/facial-parts.md). Explicit facial-layer requests override the default of keeping a fixed expression on one head plate; preserve the initial expression while preparing a clean backing and independently controllable features.
4. Read [artist-redraw.md](references/artist-redraw.md) for extraction, complete-part redraw and hidden overlap completion. For residual foreground marks on a backing, broken attachment joins or duplicate rear geometry, use [backing-cleanup.md](references/backing-cleanup.md). Choose based on defects; neither split-first nor whole-part regeneration is mandatory. When coloring and separation are both requested, approve the coloring against the original drawing before freezing it as the separation baseline. The drawing, palette reference and approved colored master have different roles; do not substitute a previous separation for the colored master.
5. Use [layering.md](references/layering.md) only when selecting/running a local backend or exporting its output. Backend segmentation is a proposal, not a finished asset. Follow available image-editing tool instructions for visual edits.
6. Apply the ordered [review gates](references/review-gates.md): **A — original drawing versus coloring; B — approved coloring versus the exported rest assembly, plus isolated hidden surfaces; C — small-range motion only after B passes.** At B, explicitly list what differs and fix major visible or hidden-surface defects before motion. A previous/first separation is an implementation starting point, not the acceptance reference. Any artwork change after C returns to B; a material/color decision change returns to A. File validation, an unchanged old layer, or a generated animation is not a visual pass.

## Deliver and maintain
For layered delivery, prefer PSD plus full-canvas transparent PNG parts and layer/order metadata. Include parent/pin guides and import scripts when relevant to the requested animation application. For coloring-only delivery, provide the edited image and requested format. Reopen the PSD with a parser and verify dimensions, nonempty layers and stacking. PNG parts are not a temporal image sequence. State inferred hidden areas and tested motion limits; distinguish approximate previews from an actual AE/Cubism run. Never claim a specific cloud model identity beyond what the tool reports.

Keep original sources and the approved result. Replace outdated instructions when refining this skill instead of accumulating conflicting appendices. Remove abandoned deliverables only when authorized and after checking the replacement and its dependencies. Keep reusable model caches outside delivery archives. Use targeted crops and focused revisions to limit unnecessary generation and context use.
